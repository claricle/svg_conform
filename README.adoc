== Purpose

SvgConform is an SVG conformance processor that validates SVG documents against
defined SVG profiles, and supports automatic remediation of profile requirement
violations when possible.

SvgConform is designed to ensure SVG files meet specific requirements for different use cases, such as those required in:

* Metanorma documents
* PDF and PDF/A compliance
* IETF XMLRFC documents (RFC 7996)

SvgConform is distributed as a Ruby gem.


== Overview

=== Features

* **Profile-based validation**: Validate SVG files against predefined or custom profiles
* **Remediation**: Automatically fix common SVG conformance issues
* **Extensible architecture**: Easy to add new rules and profiles
* **Command-line interface**: Validate and fix files from the command line
* **Ruby API**: Integrate validation into Ruby applications
* **Multiple report output formats**: Text and JSON output formats
* **100% SVGCheck compatibility**: Perfect error report matching with Python svgcheck tool
* **Configurable RDF metadata support**: Choose strict or permissive RDF/Dublin Core handling
* **Generic namespace handling**: Configuration-driven foreign namespace validation


=== Concepts

SvgConform is built upon the following concepts:

SVG profile:: An SVG profile is a defined set of rules and requirements that an
SVG document must meet. These requirements represent concerns that go beyond the
SVG standards, such as accessibility or stylistic concerns.

requirement:: A specific condition or set of conditions that an SVG document must meet.

remediatory action:: An automatic fix or adjustment applied to an SVG document to address conformance issues. It may imply a lossless or lossy change.

conformance:: The degree to which an SVG document meets the requirements of a specific profile.


=== Predefined libraries

SvgConform provides predefined libraries of:

* SVG profiles
* Requirement checkers that are configurable
* Remediation actions that are configurable

In combination, it allows for the flexible definition and authoring of new
deterministic SVG profiles, with the ability to enforce specific requirements
and remediation strategies.

Each remediation action can be linked to a particular requirement to indicate
their relationship, defined in the profile.


=== Reporting

SvgConform provides detailed reporting on SVG conformance issues.

* Validation results: Summary of passed and failed checks
* Report formats: The resulting validation report can be exported
  in machine-readable formats, including JSON and YAML
* Error messages: Descriptions of specific conformance issues

Add this line to your application's Gemfile:

[source,ruby]
----
gem 'svg_conform'
----

[source,bash]
----
$ bundle install
----

Or install it yourself as:

[source,bash]
----
$ gem install svg_conform
----



== Quick start

=== Command line usage

List available profiles:

[source,bash]
----
$ svg_conform profiles
----

Validate an SVG file against a profile:

[source,bash]
----
$ svg_conform validate {svg-filename} --profile={profile-name}
----

Fix an SVG file to conform to a profile:

[source,bash]
----
$ svg_conform fix {svg-filename} --in-place --profile={profile-name}
----


=== Ruby API Usage

[source,ruby]
----
require 'svg_conform'

# Load a profile and validate
profile = SvgConform::Profile.load_from_file("config/profiles/svg_1_2_rfc.yml")
document = SvgConform::Document.new(svg_content)
result = profile.validate(document)

puts "Valid: #{result.valid?}"
puts "Errors: #{result.errors.count}"
puts "Warnings: #{result.warnings.count}"

# Apply remediations to fix issues
if !result.valid? && profile.has_remediations?
  engine = SvgConform::RemediationEngine.new(profile)
  remediation_results = engine.apply_remediations(document, result)

  puts "Applied #{remediation_results.length} remediations"
  puts "Fixed SVG:"
  puts document.to_xml
end
----


== Core Concepts

=== Profiles

A **Profile** is a collection of requirements and remediations that define a specific SVG conformance standard. Profiles target specific use cases such as IETF RFC documents, web publishing, or custom organizational standards.

Each profile consists of:

* **Requirements**: Validation checks that determine if an SVG document conforms to the profile
* **Remediations**: Automatic fixes that can be applied when requirements fail
* **Configuration**: Profile-specific settings and parameters

=== Requirements

**Requirements** are the core validation logic that check SVG documents for conformance issues. There are two types of requirements:

==== Structural Requirements

Structural requirements validate the basic structure and syntax of SVG documents:

* **NamespaceRequirement**: Ensures proper SVG namespace declarations
* **AllowedElementsRequirement**: Restricts which SVG elements are permitted
* **ViewboxRequiredRequirement**: Requires viewBox attributes on root elements

==== Logical Requirements

Logical requirements validate the content and semantics of SVG documents:

* **ColorRestrictionsRequirement**: Enforces color usage restrictions (e.g., grayscale only)
* **FontFamilyRequirement**: Controls font family usage
* **NoExternalCssRequirement**: Prevents external CSS references
* **InvalidIdReferencesRequirement**: Validates that ID references point to existing elements

=== Remediations

**Remediations** are automatic fixing actions that can resolve requirement failures. Each remediation targets one or more specific requirements through a mapping system:

* **ColorRemediationAction**: Converts invalid colors to compliant alternatives (targets: `color_restrictions`)
* **FontRemediationAction**: Fixes font family specifications (targets: `font_family`)
* **NamespaceRemediationAction**: Adds missing SVG namespace declarations (targets: `namespace`)
* **ViewboxRemediationAction**: Adds missing viewBox attributes (targets: `viewbox_required`)

==== Remediation Mapping

Remediations are mapped to requirements using the `targets` configuration in profile YAML files:

[source,yaml]
----
remediations:
  - id: "fix_invalid_colors"
    type: "ColorRemediationAction"
    description: "Convert invalid colors to black or white"
    targets: ["color_restrictions"]  # Maps to ColorRestrictionsRequirement
----

This mapping system allows:

* **Targeted fixes**: Remediations only run when their target requirements fail
* **Flexible configuration**: Multiple remediations can target the same requirement
* **Conditional application**: Remediations can be enabled/disabled per profile

=== Core components

==== Document (`SvgConform::Document`)

Wraps the Moxml XML document and provides SVG-specific functionality:

* Parses SVG content using Moxml
* Provides element traversal methods
* Handles namespace resolution
* Manages document modifications

==== Validator (`SvgConform::Validator`)

The main validation engine:

* Loads and applies profiles
* Coordinates rule execution
* Collects validation results
* Manages fixing workflow

==== Profile (`SvgConform::Profile`)

Defines a set of validation rules:

* Contains multiple rules
* Provides metadata (name, description)
* Can be loaded from YAML configuration
* Supports rule inheritance

===== Requirements (`SvgConform::Requirements::BaseRequirement`)

The core validation logic is implemented as requirements:

* Focused on single validation concerns (colors, fonts, structure, etc.)
* Reusable across multiple profiles
* Return detailed violation information with context
* Can be configured with specific parameters

===== Remediations (`SvgConform::Remediations::BaseRemediation`)

Automatic fixing actions that target specific requirement failures:

* Apply specific fixes to documents based on validation failures
* Target one or more requirement types
* Preserve document structure and validity when possible
* Can be chained together for comprehensive fixes

===== Profile System

Profiles combine requirements and remediations into cohesive validation strategies:

* YAML-based configuration for easy customization
* Support for profile inheritance through imports
* Dynamic instantiation of requirement and remediation classes
* Flexible targeting of remediations to specific requirement failures

== External compliance

SvgConform supports external compliance validation through compatibility testing and comparison with external SVG validation tools.

=== General

SvgConform provides validation report comparison capabilities that enable assessment of compatibility with external SVG validation tools. This supports migration workflows and quality assurance processes.

=== svgcheck

SvgConform supports validation compatibility testing against the Python svgcheck tool for SVG 1.2 RFC validation.

==== Testing workflow

The external compliance testing workflow involves generating reference outputs from external tools and comparing validation results:

[source,bash]
----
# 1. Generate external tool outputs for reference
svg_conform generate-svgcheck --mode both

# 2. Run compatibility verification
bundle exec ruby verify_svgcheck_compatibility.rb

# 3. Generate comparison reports
svg_conform compatibility --output compatibility-report.md
----

==== Commands

**Generate test artifacts**:

[source,bash]
----
svg_conform generate-svgcheck [OPTIONS]

Options:
  -m, --mode MODE          Generation mode: check, repair, or both (default: both)
  --fixtures-path PATH     Output directory (default: spec/fixtures/svgcheck)
  -f, --single-file FILE   Process single file only
  --force                  Overwrite existing outputs
----

**Run compatibility analysis**:

[source,bash]
----
svg_conform compatibility [OPTIONS] [FILE]

Options:
  -f, --file FILE          Analyze specific file instead of all test files
  -o, --output FILE        Output clean report to file (no color codes)
  -v, --verbose            Verbose output
----

==== Configuration

External compliance testing can be configured through profile parameters. For svgcheck compatibility with the `svg_1_2_rfc` profile, configure strict validation parameters:

[source,yaml]
----
# config/profiles/svg_1_2_rfc.yml
requirements:
  - id: "color_restrictions"
    type: "ColorRestrictionsRequirement"
    description: "Restricts colors to black and white only"
    mode: "black_white_only"
    black_and_white_threshold: 764
    allowed_colors: ["black", "white", "#000000", "#ffffff", "#FFFFFF", "none", "inherit", "currentColor"]
----

[source,yaml]
----
- id: "strict_colors"
  type: "ColorRestrictionsRequirement"
  description: "Strict black and white validation for technical documents"
  mode: "black_white_only"
  black_and_white_threshold: 764
  allowed_colors: ["black", "white", "#000000", "#ffffff", "#FFFFFF", "none", "inherit", "currentColor"]
----

This configuration enables strict validation where only exact color strings are accepted during validation, while threshold-based conversion (RGB sum ≤ 764 → black, RGB sum > 764 → white) is applied during remediation.

Features:

* **Enhanced color equivalence**: `#fff` ↔ `#ffffff` ↔ `white` (when threshold not specified)
* **Strict format validation**: When `black_and_white_threshold` is specified, only exact strings from `allowed_colors` are permitted
* **Percentage RGB support**: `rgb(100%,100%,100%)` and mixed formats handled
* **Case-insensitive processing**: `BLACK` → `black` normalization
* **RGB function support**: `rgb(255,255,255)` → `white` equivalence
* **Short hex expansion**: `#000` → `#000000` normalization
* Validates fill, stroke, and style attributes

== Violation Types and Remediability

SvgConform categorizes violations into two main types:

=== Remediable Violations

These can be automatically fixed through remediation processing:

**ColorViolation** (`color_restrictions`):

* **Remediation**: Convert using CssColor equivalence system
* **Examples**: `red` → `black`, `#f00` → `#000000`
* **Confidence**: Automatic

**FontViolation** (`font_family`):

* **Remediation**: Map to generic font families
* **Examples**: `Arial` → `sans-serif`, `Times New Roman` → `serif`
* **Confidence**: Automatic

**ContentViolation** (`forbidden_content`):

* **Remediation**: Remove forbidden elements/attributes
* **Examples**: Remove `<script>`, `onclick` attributes
* **Confidence**: Safe removal

**ReferenceViolation** (`id_reference`, `link_validation`):

* **Remediation**: Remove broken references or elements
* **Examples**: Remove `<use>` with invalid href, broken links
* **Confidence**: Safe removal

**NamespaceViolation** (`namespace`, `namespace_attributes`):

* **Remediation**: Remove invalid namespace elements/attributes
* **Examples**: Remove `<inkscape:layer>`, `custom:attr`
* **Confidence**: Safe removal

**ViewboxViolation** (`viewbox_required`):

* **Remediation**: Add missing viewBox attributes
* **Examples**: Generate from width/height dimensions
* **Confidence**: Safe structural

**StyleViolation** (`style`, `style_promotion`):

* **Remediation**: Promote or convert style properties
* **Examples**: Move `style="fill:black"` to `fill="black"`
* **Confidence**: Automatic

=== Non-Remediable Violations

These require manual intervention:

**StructuralViolation**:

* **Examples**: Malformed XML, root element not `<svg>`, invalid document hierarchy
* **Reason**: Automatic fixing could break document integrity or change meaning
* **Solution**: Manual document restructuring required

This command provides a bridge between SvgConform and the Python svgcheck tool, enabling comprehensive compatibility testing and analysis. By default, it generates both check and repair outputs in separate subdirectories.

===== Output Structure

The command creates a structured output directory with separate subdirectories for different svgcheck modes:

[source]
----
spec/fixtures/svgcheck/
├── check/          # Check-only outputs (validation without remediation)
│   ├── file1.svg.out   # Validation messages from svgcheck
│   ├── file1.svg.err   # Error messages from svgcheck
│   └── file1.svg.code  # Exit status from svgcheck
└── repair/         # Repair outputs (validation + remediation)
    ├── file1.svg.out   # Validation messages from svgcheck
    ├── file1.svg.err   # Error messages from svgcheck
    ├── file1.svg.code  # Exit status from svgcheck
    └── file1.svg.file  # Remediated SVG content
----

===== Generation Modes

**Check Mode** (`--mode check`):
- Runs svgcheck without the `--repair` flag
- Only validates SVG files and reports errors
- Generates `.out`, `.err`, and `.code` files
- No remediated content is produced

**Repair Mode** (`--mode repair`):
- Runs svgcheck with the `--repair` flag
- Validates SVG files and generates remediated content
- Generates `.out`, `.err`, `.code`, and `.file` files
- The `.file` contains the remediated SVG content

**Both Mode** (`--mode both`, default):
- Runs both check and repair modes for each file
- Generates complete output sets in both subdirectories
- Provides comprehensive data for compatibility analysis

== Extending SvgConform

=== Creating Custom Requirements

To create a custom requirement, inherit from `SvgConform::Requirements::BaseRequirement`:

[source,ruby]
----
module SvgConform
  module Requirements
    class CustomRequirement < BaseRequirement
      def initialize(id:, description:, config: {})
        super(id: id, description: description, config: config)
        @custom_option = config['custom_option'] || 'default'
      end

      def check(node, context)
        return unless element?(node)

        # Perform validation logic for individual nodes
        if node.name == 'custom-element'
          unless valid_custom_element?(node)
            context.add_error(
              requirement_id: @id,
              message: "Invalid custom element: missing required attribute",
              node: node,
              severity: @severity
            )
          end
        end
      end

      def validate_document(document, context)
        # Perform document-level validation
        super(document, context)

        # Additional document-level checks
        custom_elements = []
        document.traverse do |node|
          custom_elements << node if element?(node) && node.name == 'custom-element'
        end

        if custom_elements.length > 5
          context.add_warning(
            requirement_id: @id,
            message: "Too many custom elements (#{custom_elements.length}), consider consolidating",
            node: document.root,
            severity: :warning
          )
        end
      end

      private

      def valid_custom_element?(element)
        # Custom validation logic
        has_attribute?(element, 'required-attr')
      end
    end
  end
end
----

=== Creating Custom Remediations

To create a custom remediation, inherit from `SvgConform::Remediations::BaseRemediation`:

[source,ruby]
----
module SvgConform
  module Remediations
    class CustomRemediationAction < BaseRemediation
      def perform(document, failed_requirements)
        changes = []

        # Only run if our target requirement failed
        return changes unless targets_failed?(failed_requirements)

        document.traverse do |node|
          next unless element?(node) && node.name == 'custom-element'

          # Fix missing required attribute
          unless has_attribute?(node, 'required-attr')
            set_attribute(node, 'required-attr', 'default-value')
            changes << log_change(
              :attribute_added,
              "Added missing required-attr with default value",
              node
            )
          end
        end

        changes
      end

      private

      def targets_failed?(failed_requirements)
        # Check if any of our target requirements failed
        target_ids = ['custom_requirement'] # IDs of requirements this remediation targets
        failed_requirements.any? { |req| target_ids.include?(req.id.to_s) }
      end
    end
  end
end
----

  - id: "security_restrictions"
    type: "NoExternalCssRequirement"
    description: "Prevent external CSS references"

remediations:
  - id: "fix_namespace"
    type: "NamespaceRemediationAction"
    description: "Add missing SVG namespace"
    targets: ["namespace"]

  - id: "fix_custom_elements"
    type: "CustomRemediationAction"
    description: "Fix custom element issues"
    targets: ["custom_requirement"]
    config:
      default_value: "organization_default"
----

Then load the profile:

[source,ruby]
----
# Load and use the custom profile
profile = SvgConform::Profile.load_from_file('config/profiles/my_organization.yml')
document = SvgConform::Document.new(svg_content)
result = profile.validate(document)

# Apply remediations if needed
if !result.valid? && profile.has_remediations?
  engine = SvgConform::RemediationEngine.new(profile)
  remediation_results = engine.apply_remediations(document, result)
end
----

== Performance

SvgConform is designed for performance and can handle large SVG files efficiently:

* **Streaming XML parsing**: Uses Moxml for efficient XML processing
* **Lazy evaluation**: Rules are only executed when needed
* **Caching**: Profile and rule configurations are cached
* **Parallel processing**: Multiple files can be processed concurrently

=== Benchmarks

Typical performance on a modern machine:

* Small SVG (< 10KB): ~1-5ms validation time
* Medium SVG (10-100KB): ~5-20ms validation time
* Large SVG (100KB-1MB): ~20-100ms validation time
